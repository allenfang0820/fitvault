# 记录中心 V2 正式任务清单

更新时间：2026-07-17

本清单取代此前所有 DA / ALL / FIX / RCV2 执行链。旧链路围绕 PB active/superseded history 展开，已经不符合当前产品要求。

## 最新产品要求

记录中心 V2 的右侧折线图必须展示历史活动成绩序列。

例如跑步 5K：

```text
每条可计算跑步活动 -> 最佳连续 5km 窗口 -> 一个成绩点
```

当前最佳 20:12 是该序列中的最佳点，不是折线图的唯一数据来源。

采用的参考原则：

```text
Activity -> Record Metric Result -> Record Event -> Record Index
```

- Activity 是原始事实。
- Record Metric Result 是每条活动计算出的指标成绩。
- Record Event 是 PB 突破、纪录刷新等派生事件。
- Record Index 是当前最佳、周/月/年最佳等可重建缓存。
- 不把周/月/年最佳作为主事实存储。

未来 AI 价值：

- 记录中心底层数据要让 AI 能理解用户长期运动行为，而不是只读一次数据快照。
- AI 未来可以基于 activity-level metric series、PB 突破事件、季节/天气/心率/功率上下文做洞察。
- 当前阶段只建设结构化事实，不接入 AI、不调用 LLM、不写 AI insight。

UI 主结构保持不变：

```text
左侧：记录指标项
右侧：折线图 / 演进分析
```

本阶段 UI 改动不应扩大为重做页面。前端只需要把右侧折线图从 PB history 兼容数据源切换到 metric series ViewModel，并增加当前最佳高亮、纪录突破 marker 和活动成绩点列表。

## 完成标准

记录中心 V2 只有满足以下条件，才可认为数据接入完成：

- 右侧折线图展示 activity-level metric series。
- 当前最佳从 series 派生。
- 纪录刷新节点从 series 派生。
- 前端只消费后端 ViewModel。
- 切换指标不触发全量计算。
- 多运动指标状态由后端统一返回。
- 数据层可支持未来 AI 从长期成绩序列中做洞察，但当前阶段不生成 AI 内容。
