# 脉图 V2.0 macOS 打包契约摘要

## 1. 发布目标

- 产品显示版本为 `V2.0`，macOS bundle 版本为 `2.0.0`。
- 产物为 arm64 和 x86_64 两个引导式 DMG，均包含 `脉图.app` 和
  `Applications` 快捷方式。
- 新用户只安装应用即可启动；不需手工安装 Python、Node.js、npm 或 Skill。
- V1.2.0 用户可直接替换应用并保留用户数据、账号状态和 AI 配置。

## 2. 平台与分发边界

- 本契约只覆盖 macOS arm64 / x86_64。
- Windows x64、WiX 和 MSI 在独立 Windows 打包机验收，不是本轮前置条件。
- 本次通过网盘分发，不要求 Developer ID、Apple 公证或 Gatekeeper 免提示。

## 3. 发布源契约

- 发布源必须可重现，不得依赖未记录的本机文件。
- 力量解析、肌群映射、`lib/body-muscles` 及许可证必须进入发布源。
- Cesium 1.143 的 worker、wasm、widget 和核心资源必须作为一个完整版本入包。
- `track.html`、足迹 assets、帮助文档、Garmin/COROS Skill 目录与 ZIP 必须入包。

## 4. 运行时与依赖契约

- 打包使用 Python 3.12+，`garminconnect==0.3.6`、
  `garmin-fit-sdk==21.208.0`、`curl_cffi>=0.6`。
- arm64 与 x86_64 必须各自使用对应架构的 Python、PyInstaller 和 Node/npm。
- `scripts/check_python312_runtime.py` 和 `packaging_diagnostics.py` 失败时必须阻断打包。
- COROS 首次连接可由程序使用随包 npm 安装 MCP，但不得要求用户先安装 Node。

## 5. 用户数据契约

- 数据库和活动文件位于 `~/.fitvault`，不得写入 `.app` 或 DMG。
- 覆盖升级不删除或重置数据库、FIT、照片、账号 token 或 AI 配置。
- schema 升级必须幂等，升级前后 `PRAGMA integrity_check` 为 `ok`，活动数不减少。
- 验收只写临时 HOME 或真实库副本，不写用户真实库。

## 6. 质量门槛

- 当前 55 个全量失败必须按新契约分类并收敛到零失败。
- 活动去重、FIT 监听、远程同步、年度总结请求隔离必须有聚焦绿色回归。
- 力量肌群热力图、多运动详情和 Cesium 地形必须有资源/前端合同验证。
- 每项任务通过聚焦测试、`git diff --check` 和当前任务 diff review 后才可继续。

## 7. 产物门槛

- 产物文件名为 `FitVault-V2.0-macOS-arm64.dmg` 和
  `FitVault-V2.0-macOS-x86_64.dmg`。
- 产物中必须存在对应架构 Node/npm、Skill、肌群资源、Cesium 和证书链。
- 产物不含用户数据、token、Cookie、日志、真实 FIT、测试或本机绝对路径。
- 每个 DMG 记录 SHA-256、大小、架构、bundle 版本和构建时间。
- 只有新装和 V1.2.0 覆盖升级 smoke 都通过后才允许上传网盘。
