# FIT关键证据卡语义正确性优化交付手册

> 日期：2026-08-06
> 状态：Draft / Optimization Decision
> 范围：关键证据卡的事实语义、保守降级、前端文案和通用 FIT 曲线稳定性

## 1. 本次优化要解决什么

本次优化不是为了把某个设备品牌的碎片化 FIT 伪装成“标准 FIT”，而是为了把当前代码里真正的语义问题修正干净。

核心判断：

- 如果是通用语义错误，值得优化。
- 如果只是某类 FIT 更稀碎、更不完整，不值得为它做品牌特供补丁。
- 如果优化会把缺失、零值、低置信和真实事实混在一起，那不叫优化，叫造假。

## 2. 优化原则

### 2.1 FIT 事实优先

所有关键证据卡只能消费后端事实与后端结论。

必须区分：

- `missing`
- 真实观测到的 `0`
- 后端派生值
- 低置信派生值

### 2.2 不做品牌特例

本次不做：

- 百锐腾专属分支
- 迈金 / 佳明 / 其他品牌特供分支
- 为稀碎曲线强行补成连续曲线
- 为坏数据做“看起来很完整”的强插值

### 2.3 保守降级但不乱降级

保守降级是对的，但要降得准：

- 缺失速度不能当成真实停顿
- 近零距离差不能放大成离谱坡度
- 低置信派生速度不能当成完全可用
- 已经实现的指标不能因为前端兜底不严而被说成“待接入”

### 2.4 关键证据卡只说后端已经知道的事

前端可以翻译后端 reason 和 evidence，但不能补算事实。

`待接入` 只能用于真正还没实现的能力，不能拿来代替：

- `unavailable`
- `partial`
- `missing`

## 3. 本次优化的边界

### 3.1 值得优化的

- 缺失速度被零填充的问题
- stopped 过滤误用问题
- near-zero distance 导致的 grade 爆炸问题
- 前端把后端 `unavailable/partial` 统一渲染成“数据不足/待接入”的问题
- 已实现指标但文案仍然像“没接上”的问题

### 3.2 不值得继续扩大的

- 只为稀碎 FIT 做插值补全
- 只为某品牌补一套解析规则
- 只为了让卡片“看起来连续”而牺牲事实边界
- 把低质量样本包装成高质量样本

## 4. 交付目标

优化后应达到：

- Garmin / 佳明 / 迈金等常见 FIT 保持稳定
- 百锐腾这类稀碎 FIT 不再触发错误语义
- 真缺数时显示真实原因
- 已实现能力不再显示“待接入”
- 后端、前端、测试三层对同一语义保持一致

## 6. 交付口径

如果后续要做实现，唯一允许的方向是：

1. 修正通用语义错误
2. 收紧保守降级边界
3. 提升关键证据卡的原因表达
4. 用测试证明常见 FIT 不退化、稀碎 FIT 不误判

不允许的方向是：

1. 给百锐腾开特例
2. 把坏 FIT 补成好 FIT
3. 用前端文案掩盖后端缺陷
4. 用插值和猜测冒充事实
