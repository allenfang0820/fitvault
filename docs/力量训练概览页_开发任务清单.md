## 0. 执行规则

- 本清单只覆盖活动详情「概览」Tab 的基础力量训练数据和肌肉热力图。
- 力量训练复盘、历史趋势、PR、1RM、恢复、建议和 AI 解读均不在范围内。
- 首次任务前全文阅读交付手册、本清单、现有多运动契约和 JS API 合同，并落盘
  `docs/力量训练概览页_契约摘要.md`。
- 每项任务开始前刷新契约摘要并记录工程级执行提示词；只有目标、功能或合同严重偏离时，
  才重新全文阅读全部源文档。
- 每项任务按「提示词 -> 实施 -> 聚焦测试 -> diff review」执行。通过后自动进入下一项。
- FIT、版本化动作映射和数据库物化结果是唯一事实来源；前端不得补算或猜测动作、组数、
  重量、训练容量或肌群。
- 无结构化组数据时必须保留 `strength_limited / strength_unavailable`。
- 历史力量活动若受控本地 FIT 仍有结构化组，必须自动物化；“需要用户手动重导入”不再是
  可接受边界。
- 详情读取路径禁止解析 FIT；回填只能在异步 worker 或导入/同步阶段执行。
- 对真实 `user_profile.db` 执行写入前，必须先完成 dry-run、展示候选和预期更新，并取得用户
  明确确认；随后使用 SQLite 一致性备份，不得直接复制正在写入的数据库文件。
- 当前工作区包含其他未提交改动；不得 stash、reset、覆盖或格式化无关文件。
- 每项任务结束至少运行聚焦测试与 `git diff --check`；合同变更同步到
  `docs/js_api_contract.json`、Registry 和契约测试。

## 13. ST-12：非户外详情模块清理与动作中文展示

### 触发背景

截图验收发现：

- 结构化力量页右侧动作名仍显示英文 `Curl`、`Sit Up`。
- 力量页下方仍残留户外活动相关模块外壳，包括轨迹缩略图 loading、圈速统计等。
- 该问题不能只作为力量训练特例修复；有氧、恢复、泛训练等非户外详情页也不得残留户外模块。

### 目标

- 已知力量动作在后端详情 view model 中展示中文名；保留 `exercise_key` 和 raw name 追溯。
- `strength_muscle_map` 独立布局必须真正隐藏标准概览容器，CSS 不得覆盖 `hidden`。
- 非户外详情页没有 `track_map` 时隐藏轨迹主视觉区域。
- 非户外详情页没有 `indoor_segments` 或 `swim_lengths` 等真实表格合同时隐藏分段区。
- 户外耐力活动的轨迹缩略图、圈速统计和赛事照片能力保持不变。

### 允许改动

- `track.html` 的概览布局门禁、CSS hidden 防护和非户外模块可见性。
- `strength_muscle_map_v1.py` 的中文展示名映射。
- `main.py` 的 `detail.strength.exercises[].exercise_name` 展示层本地化。
- `tests/test_strength_activity_detail_contract.py`、`tests/test_strength_overview_frontend.py`、
  `tests/test_activity_detail_multi_sport_capabilities.py`。
- 交付手册、任务清单和契约摘要。

### 禁止

- 不改变 FIT 解析事实来源、肌群权重、容量计算或数据库 schema。
- 不开放力量、有氧、恢复、泛训练复盘。
- 不写生产 `user_profile.db`，不提交真实 FIT、数据库、备份或用户路径。
- 不在前端翻译或猜测未知动作；前端只消费后端字段。
