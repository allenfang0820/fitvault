# 运动生涯记录中心 V2 开发交付手册

更新时间：2026-07-17

本文是记录中心 V2 的开发交付依据。旧版本中围绕 PB active/superseded、candidate/active 写入门禁、AI summary 和两点 history 的内容全部废弃。

## 1. 目标

构建一个多运动记录中心，从历史活动中计算各类指标成绩，并展示：

- 每个指标的当前最佳。
- 每个指标的历史活动成绩序列。
- 当前最佳的 Activity 来源、窗口范围和质量证据。
- 纪录刷新节点。

## 2. 非目标

当前阶段不做：

- AI 总结。
- 训练建议。
- 路线/赛段 PR。
- 前端计算指标。
- 真实库写入型 PB 状态机扩展。
- 用 PB active/superseded 表直接驱动主折线图。

说明：AI 是未来受益方，不是当前交付内容。当前数据模型必须为未来 AI 理解用户长期运动行为打基础，但不得在本阶段调用 LLM 或写 AI insight。

## 3. 用户体验

页面结构固定：

```text
左侧：记录指标项
右侧：选中指标的历史活动成绩折线图
```

UI 不需要推倒重做。当前左侧指标项、运动 tabs、整体布局和深色视觉框架保留。改动集中在右侧图表的数据源、点位语义、当前最佳高亮、纪录突破标记和底部列表文案。

左侧指标项：

- 展示当前最佳。
- 点击后切换右侧图表焦点。
- 不承载历史成绩列表。

右侧图表：

- X 轴为活动日期。
- Y 轴为该指标成绩。
- 每个点来自一条历史活动在该指标下的计算结果。
- 当前最佳点高亮。
- 刷新纪录点标记。
- 点位可追溯 Activity 和窗口范围。

右侧底部列表：

- 展示活动成绩点。
- 显示日期、成绩、是否当前最佳、是否刷新纪录。
- 不再显示 PB `active/superseded` 状态链作为主列表。

前端接入边界：

- 从 `get_career_record_metric_series()` 读取图表 ViewModel。
- 不计算窗口。
- 不计算当前最佳。
- 不计算 PB 突破。
- 不调用 preview/rebuild/materializer。

## 4. 数据模型

必须引入或等价实现 activity-level metric series。

推荐表：

```text
career_record_metric_results
```

设计原则：

- Activity 是原始事实。
- Record Metric Result 是每条活动在某个指标下的计算成绩。
- Record Event 是从成绩序列中派生出的 PB 突破或重要节点。
- Record Index 是当前最佳、月最佳、年最佳、生涯最佳等缓存。
- 周/月/年最佳不作为主事实存储。
- 所有 index 必须可由 metric results 重建。

字段：

- `id`
- `activity_id`
- `record_key`
- `sport`
- `event_date`
- `metric_name`
- `metric_value_num`
- `metric_unit`
- `display_value`
- `range_json`
- `quality_json`
- `scope_json`
- `scope_hash`
- `resolver_version`
- `created_at`
- `updated_at`

当前最佳从该表查询派生，不以 PB 表作为主事实。

可选派生表：

```text
career_record_events
career_record_indexes
```

`career_record_events` 保存 PB 突破节点、Record Timeline 节点和重要里程碑。

`career_record_indexes` 保存可重建缓存，例如 current best、monthly best、yearly best、trend cache。

## 5. API

核心 API：

```text
get_career_record_metric_series(record_key, filters)
```

返回：

- `points`
- `current_best`
- `record_progression`
- `summary`
- `status`
- `metrics`

`get_career_records()` 只负责左侧摘要：

- record_key
- display_name
- current_best.metric.display
- current_best.event_date
- state

`get_career_record_history()` 若保留，只能作为兼容层，不能再代表主图数据源。

## 6. Resolver

跑步标准距离：

- 每条跑步活动计算最佳连续距离窗口。
- 5K、10K、半马、全马分别生成成绩点。
- 缺少距离-时间流时可 fallback，但必须降级标记。

骑行标准距离：

- 使用连续距离窗口。
- 质量门禁高于跑步。

骑行功率：

- 使用功率流窗口。

整次活动指标：

- 使用活动 summary。

游泳：

- 泳池依赖 laps/lengths/pool length。
- 公开水域依赖可靠 GPS/距离流。

## 7. 质量和状态

每个成绩点必须带质量说明：

- 数据源
- 计算口径
- 是否 fallback
- 是否可作为当前最佳
- reason_codes

不可用状态必须由后端返回，不得由前端推断。

## 8. 性能

禁止在页面切换时全量计算历史活动。

实现应采用：

- 活动导入时增量计算。
- 后台批量 backfill。
- metric result cache。
- 只读聚合 ViewModel。

## 9. 验收

以跑步 5K 为第一验收样例：

- 后端返回所有可计算跑步活动的 5K 成绩点。
- 当前最佳为 20:12。
- 图表点数不是 PB 刷新次数，而是可计算活动成绩数。
- 27:08 和 20:12 只作为纪录刷新节点。
- 前端不计算窗口。
- 切换运动无明显卡顿。

## 10. 清理要求

以下旧路径不得作为新任务依据：

- PB active/superseded 两点 history。
- candidate/active 写入门禁报告。
- AI records summary。
- DA/ALL/FIX 执行链报告。
- preview candidates 直接画图。

后续任务必须先检查是否服务于 activity-level metric series。

## 11. 未来 AI 升级基础

记录中心的数据层应支持未来 AI 从静态快照分析升级为长期用户理解。

未来 AI 可以使用：

- activity-level metric series
- Record Timeline
- PB 突破事件
- 年/月/季节表现变化
- 心率、功率、天气、爬升等上下文
- 当前最佳和历史最佳演进

当前阶段只建设这些结构化事实和可重建索引，不生成 AI 内容。
