## 1. 不变主链路

```text
Activity
  -> swim canonical facts
  -> career_record_metric_results
  -> current_best / record_progression
  -> career_record_events
  -> Records Center / Timeline
```

- `Activity` 是唯一原始事实源。
- 前端只渲染后端 ViewModel，不计算池长、距离窗口、最佳成绩、质量或里程碑。
- `career_record_metric_results` 是记录中心事实层。
- `career_record_events` 是可由 metric results 重建的派生层。
- 所有联动身份使用 `(activity_id, record_key, scope_hash)`；不得按 5K、10K 或单次活动写特例。

## 2. 游泳指标契约

| 运动 | 指标 | metric series | current best | scope | 可用条件 |
| --- | --- | --- | --- | --- | --- |
| 泳池游泳 | 50m、100m、200m、400m、800m、1500m | 必须接入 | 必须派生 | `water_scope`、`pool_length_scope`、`stroke_scope` | 可证明池长、连续 length/lap 事实、有效时长 |
| 公开水域 | 750m、1500m、1900m、3800m、5K、10K | 必须接入 | 必须派生 | `water_scope` | 统一米制距离、有效时长、目标距离容差、GPS/距离质量通过 |
| 公开水域 | 最长距离、最长历时 | 已接入，需修复联动 | 必须派生 | `water_scope` | 统一米制距离或有效时长，质量可解释 |

状态约定：

- `available`：事实完整，允许进入 chart、current best、record progression 和 timeline。
- `validation_required`：事实可展示但质量存在风险；不得静默消失，默认不进入 current best，直到明确的后端 eligibility 规则允许。
- `sample_missing`：缺少池长、长度、距离、时长或目标样本；返回稳定 reason code。
- `unsupported`：仅用于未定义的指标，不得用于 catalog 中已经承诺接入的泳池/公开水域 record key。

## 3. 源事实和单位契约

### 3.1 泳池游泳

允许作为池长事实的来源：

- FIT / provider 的 session 或 swim-length 结构化池长字段。
- 已保存的、可追溯到上述原始事实的 Activity canonical 字段。

Activity canonical 字段：

- `swim_water_scope`
- `swim_pool_length_m`
- `swim_pool_length_unit`
- `swim_pool_length_scope`
- `swim_stroke_scope`
- `swim_facts_quality_json`

后续 resolver 必须优先读取上述 canonical 字段，并兼容已有的 `pool_length_m` / `pool_length` 输入。不得从总距离、lap 数、`length_distance_m` 或显示值反推池长。

### 3.2 公开水域

所有公开水域 resolver 必须使用统一的 `_activity_distance_m()` 口径取得距离，禁止直接把 `distance` 当作米制事实。该函数必须兼容历史 Activity 中：

- `distance_m` 已是米。
- `distance` 已是米。
- `dist_km` 或历史 `distance` 是公里。

标准距离仅以米制数值与目标距离比较。目标容差、GPS 跳点、距离回退、时长缺失和手工/估算距离都必须写入 reason code 和 eligibility。

## 4. 生命周期和时间轴契约

对任意游泳 Activity 的新增、更新、重新导入、软删除：

1. 失效或重算受影响的 `career_record_metric_results`。
2. 重建同一 record key / scope 的 `current_best` 和 `record_breaking`。
3. 清理失效 `career_record_events`，并晋升下一条有效成绩。
4. 时间轴按 `(activity_id, record_key, scope_hash)` 合并同态节点：
   - 当前最佳使用 `current_best` 语义。
   - 历史突破使用 `record_breaking` 语义。
   - 同一当前最佳不得仍被表达为“刷新纪录”。

不得新增游泳专用事件表、前端补算分支或 candidate-only 终点。

## 6. 受控空态

- 缺少可证明池长：`sample_missing`，reason code `pool_length_missing`。
- 长度流缺失：`sample_missing`，reason code `lap_length_stream_missing`。
- 公开水域距离或时长缺失：`sample_missing`，对应 `distance_missing` / `elapsed_time_missing`。
- 标准距离不在容差内：该 Activity 不为该 record key 生成 point，并保留 `distance_outside_5_percent` 诊断。
- GPS / 距离质量不足：`validation_required`，保留 reason codes；不得被伪装成正式 current best。
