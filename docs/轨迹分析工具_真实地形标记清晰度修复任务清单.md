# 轨迹分析工具真实地形标记清晰度修复任务清单

本清单修复真实地形下 CP、里程、最高点 / 坡顶标记仍然模糊的问题。三类标记使用不同渲染链路，必须分别测量、修复和验收。

## 0. 根因结论

### 0.1 CP 与最高点 / 坡顶 billboard

- `buildMapPinCanvasImage()` 使用固定逻辑尺寸 `64×84` 和固定 backing scale `2`，生成 `128×168` PNG。
- CP 显示为 `32×42`；最高点为 `30×40`；普通坡顶为 `24×32`。源图与目标尺寸存在不同缩放比，最高点和普通坡顶还不是严格等比整数缩放。
- CP 使用 `scaleByDistance: 1.14→0.72`，最高点 / 坡顶使用 `1.05→0.68`，相机移动时持续产生非整数目标像素尺寸和纹理重采样。
- pin cache key 只含颜色 / 类型，不含 DPR、backing scale 或目标尺寸。窗口跨 Retina / 非 Retina 显示器或缩放比例变化后，旧纹理不会重建。

高置信主因：**固定 backing 纹理被多次、非整数、连续缩放。**

### 0.2 里程标记

- 里程点当前不是 canvas billboard，而是 `PointGraphics + LabelGraphics`。
- 真实地形 label 字体为 `12px`，清晰度依赖 Cesium glyph atlas、drawing buffer 和 WebView 显示比例。
- 里程层级当前通过 1km / 5km / 10km distance display condition 控制，该语义必须保留。

高置信结论：**里程问题不能通过调整 CP / peak pin PNG 单独解决。**

### 0.3 全局放大因素

- Viewer 为 macOS WebView shader 兼容设置 `MSAA=1` 并关闭 FXAA。
- 当前没有明确记录 `devicePixelRatio`、`viewer.resolutionScale`、canvas client size 与 drawing buffer size的比例。
- `RELATIVE_TO_GROUND` 和 depth test 主要导致遮挡、裁切或抖动，不直接降低纹理分辨率，但半遮挡可能被用户感知为模糊。

中等置信结论：**drawing buffer / DPR 与抗锯齿配置可能放大模糊，但必须测量后才能调整。**

## 1. 冻结产品边界

- 保留 CP 展示、新增、编辑、删除和侧栏联动。
- 保留 1km / 5km / 10km 里程层级和开关。
- 保留最高点优先于普通坡顶的层级与开关。
- 保留 distance declutter 和有限 depth-test 穿透策略。
- 保留真实地形 `RELATIVE_TO_GROUND`、marker offset、vertical exaggeration 和 hillshade。
- 不恢复 SVG text、SVG filter、emoji 纹理或 point + billboard 双重绘制。
- 不用统一放大所有 marker 代替清晰度修复。
- 不修改 DEM provider / cache、相机一致性、FIT / GPX、DB、剖面、复盘或 AI。

## 2. 量化门禁

| 项目 | 门禁 |
| --- | --- |
| canvas backing | 与逻辑尺寸和实际 DPR 对齐，cache key 包含影响像素密度的参数 |
| billboard 宽高比 | 源图与目标图比例一致，误差不超过 `1%` |
| 纹理缩放 | 近景关键标记不得依赖连续非整数 `scaleByDistance` 获得基础尺寸 |
| drawing buffer | 记录并验证 drawing buffer / CSS canvas / DPR / resolutionScale 比例 |
| CP / 最高点 | 100% 截图下边缘与中心圆可分辨，无明显双影或糊边 |
| 里程 | `1 km`、`5 km`、`10 km` 数字可辨，层级规则不变 |
| 遮挡 | marker 不被地形切掉主体；允许符合 distance declutter 的隐藏 |
| 性能 | 不因清晰度修复造成持续明显掉帧；具体基线在 MCLR-00 测量后冻结 |

## 3. 全局执行规则

- 每项任务开始前刷新 CDEM 契约摘要并落盘工程级提示词。
- 每项任务测试全绿后才能进入下一项。
- 工作区存在无关 dirty 修改，不得 stash、reset、覆盖或格式化。
- 任何 viewer resolution / AA 改动必须先通过独立 POC；兼容失败时回滚，不影响 pin / label 局部修复。
- 自动化不能替代 Retina / 非 Retina 真实桌面 UI 截图验收。

## 5. 任务详情

### MCLR-00：像素、DPR 与渲染基线

状态：`Planned`　优先级：P0　性质：审计 / 测量 / 不改生产行为

目标：量化源纹理、Cesium 目标尺寸、实际屏幕像素、drawing buffer 和地形遮挡，区分纹理模糊、glyph 模糊和半遮挡。

必做：

- 记录 CP、最高点、普通坡顶源 canvas 与显示宽高、实际 `scaleByDistance` 区间。
- 记录里程 point pixel size、label font、outline 和 distance condition。
- 在真实 pywebview 记录 DPR、`viewer.resolutionScale`、canvas client size、drawing buffer size。
- 使用近 / 中 / 远三档距离和 2D / 中间 / 3D 三档视角截图。
- 在 Retina 与可用的非 Retina / 缩放显示环境比较。
- 分别标注纹理重采样、字体图集、地形裁切、深度混合和截图缩放现象。

允许修改：文档、基线报告和只读诊断测试；不改 `track.html` 生产行为。

验收：CDEM 聚焦 pytest、`git diff --check`；基线报告不得把未执行设备写成通过。

完成标准：三个 marker 类型各有独立证据；冻结性能和像素基线；给 MCLR-01 / 03 / 04 明确输入。

---

### MCLR-01：HiDPI pin 纹理合同

状态：`Planned`　优先级：P0　前置：MCLR-00

目标：让 CP、最高点和坡顶 canvas backing 与逻辑尺寸、实际 DPR 和目标 billboard 尺寸一致。

必做：

- 定义 canonical 逻辑尺寸和严格一致的源 / 目标宽高比。
- backing scale 基于受控 DPR，而不是固定常量 `2`。
- cache key 包含类型、颜色、DPR、逻辑尺寸和视觉版本。
- DPR 或显示比例变化时可安全重建纹理缓存。
- canvas path、stroke 和中心圆按逻辑坐标绘制，避免半像素描边。
- 继续使用 canvas / PNG 或 Cesium 可接受的 bitmap，不恢复 SVG / emoji。

允许修改：`track.html`、CDEM 聚焦测试、契约摘要和任务记录。

验收：canvas backing 尺寸测试、cache key 测试、DPR 1 / 1.5 / 2 fixtures、JS 语法、`git diff --check`。

完成标准：源 / 目标宽高比误差不超过 1%；同一显示环境不复用错误 DPR 纹理；CP / peak 功能不变。

---

### MCLR-02：billboard 距离缩放策略

状态：`Planned`　优先级：P0　前置：MCLR-01

目标：减少 CP / peak billboard 在连续距离下的非整数纹理重采样，同时保留远近层级和 declutter。

必做：

- 评估固定基础尺寸 + distance display condition、离散 LOD 纹理或受控缩放档位。
- 近景关键标记使用稳定整数逻辑尺寸。
- 最高点与普通坡顶保持优先级差异，但不共享不匹配的目标尺寸。
- 相机移动时不出现尺寸抖动、突然跳档或 marker 堆叠。
- 不通过无限放大或关闭距离裁剪获得清晰度。

允许修改：`track.html`、CDEM 聚焦测试和任务记录。

验收：缩放策略合同、近中远截图、marker 数量 / distance condition 回归、JS 语法、`git diff --check`。

完成标准：连续非整数缩放不再承担基础显示尺寸；近中远均可识别且 declutter 保持。

---

### MCLR-03：里程标记清晰度方案

状态：`Planned`　优先级：P0　前置：MCLR-00

目标：单独解决 point + 12px Cesium label 链路的模糊，不把 CP / peak 的 canvas 结论直接套用。

候选方案：

- A：保留 PointGraphics + LabelGraphics，调整整数 font / outline / pixel offset 并验证 glyph atlas。
- B：使用缓存的 HiDPI canvas badge / billboard 统一数字与底形。

必做：

- 用相同路线、相机、DPR 对比 A / B 清晰度、遮挡和性能。
- 保留 1km / 5km / 10km distance 层级。
- 保留里程开关和 `km.km` 真实事实来源。
- 不在前端重算里程，不改变 marker 数量语义。

允许修改：POC fixture、`track.html` 最终选定方案、CDEM 测试和任务记录。

完成标准：有截图和性能证据选择 A 或 B；1 / 5 / 10km 标签清晰可辨；里程功能合同保持。

---

### MCLR-04：Viewer resolution 兼容 POC

状态：`Planned`　优先级：P1　前置：MCLR-00

目标：确认 drawing buffer 是否是全局模糊放大因素，并判断是否需要受控 `viewer.resolutionScale`。

必做：

- 测量 DPR、client size、drawing buffer 和当前 resolution scale。
- 对比 resolution scale `1 / 1.5 / 2` 或设备 DPR 上限方案。
- 测量静态清晰度、相机移动帧时间、内存和 terrain tile 体验。
- 验证 macOS WebView / ANGLE / Metal shader 稳定性。
- pin 局部修复已足够时允许结论为“不改全局 resolution”。

禁止：未经 POC 恢复 FXAA、提高 MSAA、动态光照或阴影 shader。

完成标准：形成采用 / 不采用结论和回滚条件；失败不阻塞 MCLR-01 / 02 / 03 局部修复。

---

### MCLR-05：地形遮挡与高度稳定

状态：`Planned`　优先级：P1　前置：MCLR-02, MCLR-03

目标：排除 marker 主体被地形半遮挡、深度混合或 offset 不足造成的“像模糊”现象。

必做：

- 验证 CP、里程、最高点在山脊、坡面、谷地的完整轮廓。
- 检查 `RELATIVE_TO_GROUND` offset、vertical origin、pixel offset 和 depth-disable distance。
- 保持 marker 不悬浮过高、不穿地、不无限穿透。
- 切换标准 / 真实地形后 marker 不闪烁、不重复、不残留旧纹理。

允许修改：`track.html` marker 显示参数、CDEM 测试和任务记录。

完成标准：主体无半遮挡糊边；高度策略和 declutter 保持；相机切换任务合同不受影响。

---

### MCLR-06：自动化与像素合同

状态：`Planned`　优先级：P0　前置：MCLR-01 至 MCLR-05

目标：把 DPR、尺寸、cache、缩放和三类 marker 功能固化为自动化门禁。

必做：

- canvas backing、宽高比、DPR cache key 和视觉版本测试。
- 禁止 SVG text / filter / emoji pin 回归。
- CP / peak 不恢复 point + billboard 双绘制。
- 里程 1 / 5 / 10km 层级和开关测试。
- Viewer resolution POC 结论合同。
- CP 编辑、最高点优先级、distance declutter、terrain height reference 回归。

验收：完整 CDEM / DEM cache / thumbnail / detail 回归、JS 语法、`git diff --check`。

完成标准：自动化全绿；测试不把字符串存在等同于真实视觉清晰。

---

### MCLR-07：真实 UI 验收与完成报告

状态：`Planned`　优先级：P0　前置：MCLR-06

目标：在真实 pywebview、真实 DEM、不同 DPR 和相机距离下完成发布验收。

验收矩阵：

- 城市跑、山地 / 越野跑、骑行爬坡。
- Retina 2x；可用时增加非 Retina / 缩放显示。
- 2D、中间角度、3D。
- 近、中、远距离。
- 标准 / 真实切换后首次帧和 settle 后稳定帧。
- CP、普通里程、5km / 10km、最高点、普通坡顶。

必须记录：原始 100% 截图、DPR / drawing buffer 信息、清晰度结论、帧时间或主观卡顿、shader 错误、未执行项。

允许修改：完成报告、任务状态；真实 UI 暴露缺陷时才最小修改生产代码与测试。

完成标准：三类 marker 均有通过 / 失败证据；未执行环境不写成通过；MCLR-00 至 07 全部完成后才能将 CDEM-13 标记 `Completed`。
