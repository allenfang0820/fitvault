# 脉图 V2.0 Windows 打包继续审查清单

更新时间：2026-08-03

适用范围：Windows x64 打包机、PyInstaller 构建、WiX/MSI、Windows 真机 smoke。

本清单只记录 Windows 线需要继续独立审查的内容，不重复 macOS 已完成项。

## 1. 打包环境闸门

- [ ] Windows Python 3.12 环境可用，且使用项目约定的 `.venv312` / 等价 Windows 虚拟环境。
- [ ] `scripts/install_packaging_deps.ps1` 可执行且依赖安装结果与 `constraints.txt` 一致。
- [ ] `scripts/check_python312_runtime.py` 通过。
- [ ] `python -m packaging_diagnostics` 通过，且不会把 Windows 打包机绝对路径写入产物。
- [ ] `garminconnect==0.3.6`、`garmin-fit-sdk==21.208.0`、`curl_cffi>=0.6`、`requests` 等版本与诊断一致。
- [ ] `runtimes/node-win-x64` 完整，`node.exe` / `npm.cmd` 均可用，架构为 x64。

## 2. spec / 资源契约

- [ ] `HikingTrackAnalyzer.spec` 在 Windows 上能正常收集：
  - [ ] `runtimes/node-win-x64`
  - [ ] `skills/garmin-stats`
  - [ ] `skills/coros-stats`
  - [ ] `skills/*.zip`
  - [ ] `track.html`
  - [ ] `lib/`
  - [ ] `assets/`
- [ ] Windows 侧仍保留 `FitVaultCLI.exe` 兼容路径，但新主入口以 App 内账号连接为主。
- [ ] `installer/FitVault.wxs` 与 `installer/maitu.ico` 内容、快捷方式、产品名、图标引用正确。
- [ ] `build_dependency_manifest.json` 不暴露 Windows 本机绝对路径、账号、token 或用户目录。

## 3. 构建产物审查

- [ ] PyInstaller 成功生成 Windows 安装产物。
- [ ] 产物文件名、版本号与 V2.0 口径一致。
- [ ] 产物内不包含 `tests`、`pytest`、开发报告、真实 FIT、数据库、日志、Cookie、token。
- [ ] 产物内包含对应架构的 Node/npm runtime、Skill、Cesium、肌群热力图和帮助文档。
- [ ] 安装/解包后不会依赖用户额外安装 Python、Node 或 Skill。

## 4. Windows 启动与功能 smoke

- [ ] 首次启动能自动创建 `~\\.fitvault\\user_profile.db` 与受控 `tracks` / `imports` / `logs` 目录。
- [ ] Windows 首启日志写入 `%USERPROFILE%\\.fitvault\\logs\\startup.log`。
- [ ] 不安装系统 Python/Node 也能启动。
- [ ] 本地 FIT 导入可用。
- [ ] ZIP 导入可用，且中文文件名/编码兼容正常。
- [ ] 活动详情可打开。
- [ ] 力量训练动作组与肌肉热力图可显示。
- [ ] 轨迹分析工具的标准地形与真实地形回退正常。
- [ ] 运动生涯、记录中心、年度总结页可打开，空库不报错。

## 5. 账号连接与平台差异

- [ ] Garmin App 内登录路径可用，失败时错误脱敏，不直接透传底层异常。
- [ ] COROS 连接路径可用，MCP / 浏览器流程状态正常。
- [ ] Windows 上旧 legacy 登录入口返回 `unsupported_legacy_login` 并正确引导到账号连接中心。
- [ ] Windows 端不要求用户手工安装开发环境。

## 6. 真机验收结论

- [ ] Windows 安装后可直接运行并完成核心 smoke。
- [ ] Windows 打包验证完成后，再决定是否补充 MSI / 其他发布产物。
- [ ] 任何未完成项都必须明确保留，不得因 macOS 已完成而自动勾选。
