# 轨迹分析工具地形切换相机一致性修复任务清单

本清单解决标准地形与真实地形切换时的视觉视角跳跃。任务只修复相机与新旧地表之间的相对关系，不改变当前产品控件分工，也不重做轨迹分析工具。

一句话目标：

**图层切换前后保持同一用户视图；地形可以变化，路线 framing、2D / 3D slider 和用户相机意图不能被重置。**

## 0. 冻结决策

### 0.1 控件语义

- 2D / 3D slider 只控制相机 pitch / 视角连续过渡。
- 标准 / 真实地形按钮只控制 terrain provider 和对应显示层。
- slider 不触发 DEM 下载，不切换 provider。
- 图层按钮不改 slider 值，不自动归北，不重新 fit 路线。
- 标准地形在 slider 位于 3D 端时允许显示三维透视。

### 0.2 相机一致性定义

本任务保持的是“同一用户视图”，而不是相机 ECEF 世界坐标机械不变。

切换前必须捕获：

- 当前屏幕中心对应的地理锚点经纬度。
- 锚点来源：地表拾取或路线中心 fallback。
- `heading / pitch / roll`。
- 相机到锚点的焦点距离 `rangeM`。
- `map-view-slider` 精确值。
- 当前 terrain mode、相机 controller 和切换 revision。

目标地形稳定后必须保持：

- 同一锚点经纬度。
- 同一 heading、pitch、roll。
- 同一 slider 值。
- 相机到新地表锚点的距离基本不变。
- 屏幕中心和路线 framing 不出现重新适配式跳动。

### 0.3 量化门禁

| 项目 | 门禁 |
| --- | --- |
| slider 值 | 切换前后完全一致，差值 `0` |
| heading / pitch / roll | 各自绝对差不超过 `0.5°` |
| 地理锚点 | 经纬度不变；桌面实测中心投影漂移不超过 `12px` |
| range | 切换前后相对差不超过 `2%`，除非 Cesium 防穿地安全约束生效 |
| 路线 framing | 不调用路线 fit；可见路线包围盒尺度变化不超过 `5%`，地形遮挡导致的自然变化除外 |
| 过渡时长 | 建议 `300–500ms`，不得出现二次回弹 |
| slider / provider 解耦 | slider block 不出现 provider / DEM 调用 |

如 Cesium 防穿地需要调整 range，必须记录实际调整原因和幅度，不得静默扩大视野。

## 1. 全局执行规则

- 每项任务开始前刷新 `docs/轨迹分析工具_Cesium_DEM_POC_契约摘要.md`，并落盘该任务工程级提示词。
- 只有当前任务测试全绿，才能开始下一任务。
- 任务偏离到 provider、DEM cache、活动事实、FIT / GPX、DB、剖面、复盘或 AI 时，必须重新全文阅读相关合同后再继续。
- 每项任务开始前执行 `git status --short`，不得 stash、reset、覆盖或格式化无关 dirty 文件。
- 海拔墙保持彻底退役。
- 真实地形保留现有 ArcGIS provider、`verticalExaggeration = 1.6`、hillshade、轨迹贴地和 marker 高度策略。
- 标准地形保留 `EllipsoidTerrainProvider` 和现有 FIT 海拔视觉策略。
- 不使用 `flyToBoundingSphere`、路线 bbox 重新 fit 或强制 slider 改值掩盖跳变。
- 相机快照仅存在前端内存，不写 DB、不进入 AI snapshot、不持久化。

### CTCAM-01：地形相机快照合同

优先级：P0
状态：`Planned`
前置：CTCAM-00

目标：新增只读地形相机快照，稳定描述用户切换图层前看到的视图。

建议快照：

```js
{
  revision,
  sourceTerrainMode,
  sliderValue,
  heading,
  pitch,
  roll,
  anchor: { longitude, latitude, height, source },
  rangeM,
  cameraPositionWC,
  capturedAt
}
```

允许修改：`track.html`、CDEM 聚焦测试、契约摘要和任务记录。

必做：

- 实现 `captureTerrainCameraSnapshot()` 或同等职责 helper。
- 优先使用 canvas 中心射线与 `scene.globe.pick()` 捕获地表焦点。
- 地表拾取失败时使用 `appState.centerPosition` 并记录 fallback 来源。
- 使用当前 camera 与 anchor 的实际距离，不从路线 bbox 重新计算。
- 精确读取 slider 值，不反向改写 slider。
- 快照捕获不得改变 camera transform、姿态、range 或 ownership。

禁止：不调用 `lookAt`、`setView`、`flyTo`；不写 DB、localStorage 或后端；不从 DEM 改写 FIT 海拔。

验收：CDEM 聚焦 pytest、JS 语法、`git diff --check`。

### CTCAM-02：地形切换事务与竞态控制

优先级：P0
状态：`Planned`
前置：CTCAM-01

目标：把地形切换改造成有 revision 的事务，防止异步 provider、tile settle 和用户操作互相覆盖。

允许修改：`track.html`、CDEM 聚焦测试、契约摘要和任务记录。

必做：

- 为每次 terrain 选择生成递增 revision / token。
- 每个异步阶段提交前确认 token 仍是最后用户意图。
- 标准→真实、真实→标准和失败回退使用同一事务边界。
- 过期 Promise 不得更新 provider、UI、entity 或 camera。
- 加载期间如用户主动操作相机，用户操作优先，不恢复旧快照造成回弹。
- 自动漫游、惯性缩放或 slider drag 活跃时定义明确处理；建议停止自动动画后捕获，真实用户拖拽优先。

禁止：不增加后端锁、线程、DB 状态或长期缓存；不改变 provider 选型。

验收：CDEM / DEM cache pytest、JS 语法、`git diff --check`。

完成标准：快速 `真实→标准→真实` 最终状态与最后意图一致；用户主动相机操作不被旧事务覆盖。

验收：CDEM 聚焦 pytest、JS 语法、`git diff --check`。

完成标准：标准、真实、height unavailable 三条路径均可判定；锚点经纬度不变；超时不永久阻塞切换。

### CTCAM-04：平滑相机恢复

优先级：P0
状态：`Planned`
前置：CTCAM-03

目标：根据快照和目标地表锚点，在不重新 fit 路线的情况下恢复相同视角与屏幕尺度。

必做：

- 使用快照 heading、pitch、roll、range 和 slider 值。
- 以目标地表锚点为焦点，不使用路线 bbox 或 entity bounding sphere。
- 过渡建议 `300–500ms`，只执行一次，不出现二次回弹。
- 完成后统一释放 `lookAtTransform(Cesium.Matrix4.IDENTITY)`。
- 接入独立 `terrain-switch` camera ownership；用户操作优先级高于自动恢复。
- 防穿地只允许最小安全距离调整，并记录原因。

禁止：禁止 `flyToBoundingSphere`、改 slider、自动归北、强制 pitch 或路线重新 framing。

允许修改：`track.html`、CDEM 聚焦测试、契约摘要和任务记录。

验收：CDEM 聚焦 pytest、JS 语法、`git diff --check`。

完成标准：满足 0.3 量化门禁；slider 精确值不变；无新增路线 fit。

### CTCAM-05：provider / entity / camera 时序集成

优先级：P0
状态：`Planned`
前置：CTCAM-04

目标：把快照、provider、视觉模式、tile settle、entity refresh、锚点和相机恢复组合为单一可审计流程。

固定顺序：

```text
冻结用户意图 / revision
  → 捕获相机快照
  → 切换目标 provider 与视觉模式
  → 等待目标 terrain 稳定或超时
  → 按目标模式重建轨迹 / marker
  → 解析同经纬度目标地表锚点
  → 平滑恢复相机
  → 提交 mode / UI 并释放 ownership
```

必做：

- 标准→真实、真实→标准使用同一主链路。
- 失败回退标准地形也按快照恢复视图。
- 每次有效切换只执行一次 entity refresh 和一次 camera restore。
- 真实地形继续保留 completed / remaining、clamp、CP、里程和最高点策略。
- 标准地形继续保持 FIT 海拔视觉轨迹。
- slider block 继续不含 provider / DEM 调用。

允许修改：`track.html`、CDEM 聚焦 / thumbnail 测试、契约摘要和任务记录。

验收：CDEM、DEM cache、thumbnail pytest；JS 语法；`git diff --check`。

完成标准：失败回退不改变 slider、路线 framing 或活动事实；全部既有轨迹工具合同保持通过。

### CTCAM-06：自动化与竞态回归

优先级：P0
状态：`Planned`
前置：CTCAM-05

目标：把相机一致性、最后意图生效和失败回退固化为自动化合同。

必做场景：

- 标准→真实、真实→标准。
- provider 创建失败、tile settle 超时。
- 快速 `真实→标准→真实`。
- 加载期间用户拖动 slider、平移、缩放或旋转。
- 2D、中间角度、3D 三种状态。
- 自动漫游运行时切换。
- 路线未加载时点击真实地形。

必须锁定：slider 不变；相机指标满足 0.3；过期 revision 不提交；无 `flyToBoundingSphere` / 路线 fit；provider 与 slider 解耦；FIT / DEM 高度事实边界不变。

允许修改：测试文件；只有测试暴露明确合同问题时才最小修改 `track.html`。

验收：完整 CDEM / detail 回归、JS 语法、`git diff --check`。

完成标准：所有故障与竞态场景有自动化证据；不得只靠字符串存在宣称真实视觉通过。

### CTCAM-07：真实 UI 验收与完成报告

优先级：P0
状态：`Planned`
前置：CTCAM-06

目标：在真实 pywebview、ArcGIS terrain 和真实轨迹数据下确认切换无跳跃，形成最终完成报告。

真实轨迹矩阵：

| 轨迹 | 重点 |
| --- | --- |
| 城市跑 | 低起伏下标准 / 真实切换与屏幕尺度 |
| 山地 / 越野跑 | 高 DEM 高差、垂直夸张、坡顶 / 最高点 |
| 骑行爬坡 | 长路线、复杂 framing、进度和 marker 可读性 |

每条轨迹分别验证：2D、中间角度、3D；标准→真实→标准；网络失败回退；快速反向切换；切换后立即操作相机、归北和 slider。

视觉门禁：路线中心不突然离屏；不自动放缩、归北或重置 pitch；无二次回弹；真实地形立体感、marker 和底部剖面正常；标准地形 3D 仍可用。

允许修改：可新增完成报告和回填任务状态；只有真实 UI 暴露明确缺陷时才最小修改生产代码与测试。

验收：完整 CDEM / detail 回归、JS 语法、`git diff --check`。

完成标准：三类轨迹、三种 slider 状态和往返切换均有明确证据；未执行场景不得写成通过；CTCAM-00 至 CTCAM-07 全部完成后，CDEM-12 才可标记 `Completed`。
