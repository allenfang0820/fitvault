# 脉图 V2.0 macOS 打包基线审计报告

## 1. 审计边界

- 本报告冻结 V2.0 macOS arm64 / x86_64 打包修复的起始状态。
- 当前工作区包含大量尚未提交的产品改动；后续任务必须保留这些成果，不得
  `stash`、`reset`、`clean` 或覆盖无关文件。
- Windows、Developer ID 签名、Apple 公证和 Gatekeeper 免提示不在本轮范围。
- 用户真实数据库不参与写入式验证；升级验证只使用临时副本。

## 3. 发布源分类

### 必须进入 V2.0 发布源并由 spec 收集

- 主程序、后端模块、`track.html`、帮助文档和 `docs/js_api_contract.json`。
- `strength_fit_parser.py`、`strength_muscle_map_v1.py`、
  `strength_muscle_resolver.py`。
- `lib/body-muscles/` 的运行文件及 `LICENSE`、`NOTICE`、`VENDORED.md`。
- 完整且版本一致的 `lib/Cesium/` 1.143 worker、wasm、widget、Assets 和
  ThirdParty 资源。
- 足迹地图 assets、Garmin/COROS Skill 目录及 ZIP。
- 对应架构的 Node/npm runtime、Python 运行依赖和证书链。

### 必须纳入版本控制但不进入安装包

- 对上述功能提供回归保障的 `tests/test_strength_*`、
  `tests/test_track_cesium_dem_contract.py`、
  `tests/test_track_dem_session_cache.py` 及必要 fixture。
- 打包脚本、依赖声明、诊断脚本、spec、发布合同测试和发布文档。

### 开发或审计资料，不进入安装包

- `docs/` 下的开发任务清单、交付手册、完成报告和本审计报告。
- `scripts/probe_strength_fit.py` 等人工探针。
- `tests/`、pytest、测试 fixture 和开发期 POC 页面。
- 用户数据库、FIT、照片、token、Cookie、本机日志、缓存及任何私密凭据。

此分类只定义发布和打包边界，不决定当前未跟踪文件是否应删除；是否纳入版本
控制由 REL-01 按生产依赖和测试合同逐项确认。

## 6. REL-00 结论

审计基线已冻结。后续任务能够区分既有 dirty worktree、必须进入发布源的运行
资源、仅纳入版本控制的测试资源及明确排除的开发/用户数据。REL-01 必须从此
基线继续，优先解决力量模块与 Cesium 1.143 完整资源尚未收敛的问题。
