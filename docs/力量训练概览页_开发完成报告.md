# 脉图力量训练概览页开发完成报告

> 状态：Completed  
> 完成日期：2026-07-28  
> 产品基线：`docs/力量训练概览页_开发交付手册.md`

## 1. 交付范围

本次只交付力量训练活动详情「概览」页：基础训练指标、动作与训练组、前后人体肌肉热力图、
覆盖率与基础双向联动。力量训练复盘、趋势、PR、1RM、疲劳、恢复、建议和 AI 解读均未开放。

页面事实链路固定为：

```text
FIT raw messages
  -> 导入/同步阶段规范化
  -> activities JSON 物化
  -> get_activity_detail_summary/get_activity_detail
  -> track.html 只读渲染
```

详情读取不重新打开 FIT；前端不计算训练容量、热力分数、覆盖率、占比或等级。

## 2. 已交付能力

- 解析 `set_mesgs`、`exercise_title_mesgs`、`workout_step_mesgs`，保留组序、动作来源、组类型、
  次数、重量与时长。
- 将 `strength_sets_json`、`strength_summary_json`、`muscle_heatmap_json` 幂等写入活动行；旧行
  和无结构化动作组保持 `NULL`。
- 工作组统计排除热身、放松和恢复组；重量缺失保留次数，已知重量组才进入总训练容量。
- 使用版本化 `strength_muscle_map_v1` 生成 12 个业务肌群区域的相对分布、覆盖率、等级和
  未映射计数；未知动作留在表格中但不进入热力图。
- 有结构化动作组时返回 `strength_muscle_map / strength_sets / has_structured_sets=true` 和
  `detail.strength`；旧活动、缺失或异常物化数据保持受限态。
- 前端使用独立宽布局展示 6 个基础指标、前后人体图和动作组表；支持肌群到动作、动作到
  肌群的鼠标、触摸与键盘联动，并在切活动、关闭和加载失败时销毁图表及清空状态。
- 全未映射时显示明确空态；人体图库加载失败时降级为中文文字肌群列表。

13 stars，不宣称为成熟方案。

## 5. 浏览器验收

### 桌面 1440 x 1000

- 力量 root 宽 1334px，未继承轨迹图 260px 约束。
- 正面与背面人体均显示，单图约 363 x 460px；2 个 SVG 非空。
- 仅 26 个已映射路径可聚焦，63 个无业务数据路径从交互与无障碍树移除。
- 标准多运动概览隐藏；动作表没有横向溢出。
- 长动作名、热身组、缺重量组、已知容量和未映射动作均可读。

### 移动 390 x 844

- 只显示一个 258 x 480px 人体视图；正面/背面分段控件可切换且 `aria-pressed` 同步。
- 页面总宽保持 390px，无全局横向溢出。
- 动作表容器宽 282px、内容宽 520px，可横向滚动至 229/238px，核心列不与其他内容重叠。
- 深色主题下指标、图例、人体、选择摘要与动作表均保持可读。

### 交互与降级

- 桌面和移动视口点击肌群后，相关动作高亮、无关动作弱化；摘要显示中文等级、组数、占比
  和动作数。未执行独立物理触屏设备手测。
- 点击动作后，主要和辅助肌群按后端映射更新；动作行 Enter/Space、肌群路径 Enter/Space
  均可切换。
- 关闭详情后力量 root 为 hidden、DOM 清空、移动视图复位为正面。
- `mode=unmapped` 显示“已记录动作暂未建立肌群映射”，不显示无作用的前后切换。
- `library=missing` 显示 6 个中文文字肌群按钮，选择联动保持有效。
- 最终正常 POC 重新加载后无新增 console error。

## 6. 已知边界

- 历史力量活动不会在详情读取时补解析；需要重新导入原 FIT 才能获得结构化数据。
- 动作到肌群映射是版本化静态表，不使用 LLM，也不推断左右侧。
- 热力图表达已记录动作的相对训练分布，不代表肌电激活、疲劳或恢复状态。
- 自重或重量缺失组可按次数进入相对分布，但不进入公斤训练容量；总容量只代表已知重量部分。
- 上游人体图库社区体量有限，因此保留本地固定版本、业务适配层和无库文字降级。

## 7. 审查结论

ST-01 至 ST-06 的逐项测试与 review 均无剩余阻断问题。最终累计 review 未发现前端补算、
详情重读 FIT、旧力量活动误升级、未知动作污染热力图或力量复盘被意外开放。工作区其他既有
改动未被重置、暂存、提交或清理。
