## 冻结合同

### 事实、职责与兼容性

- FIT -> `fit_engine.py` -> canonical Activity / Resolver -> 后端 view model -> UI 是唯一事实链路；前端和 AI 不得生成、补算或猜测运动事实。
- `metrics_registry.py` 是运动类型归一化、`review_mode`、`detail_surface_mode`、`overview_capabilities` 和 `review_profile` 的唯一权威来源。前端本地判断只允许作为老数据兼容 fallback。
- 保留既有 `normalize_review_sport_type()`、`get_review_mode()`、`get_review_capabilities()` 语义和公开字段；本轮只扩展，不改名或删除。
- `get_activity_detail()` 的 `record.detail` 是概览 view model；`get_fatigue_review()` 是复盘页唯一权威数据源；AI 仅读取其后端生成的 compact snapshot。
- `unavailable` 和 `not_applicable` 的主值必须是 `null`，不能以 `0` 冒充正常或可用数据。
- 前端 JSON 和 AI prompt 不得包含 raw records、points、`shadow_diff`、`shadow_diff_json`、`diff` 或 debug-only 字段。

### 冻结枚举

`detail_surface_mode`：

```text
endurance_outdoor
endurance_indoor
swim_pool
swim_open_water
strength
mobility_recovery
skill_session
generic_session
not_supported
```

`review_profile`：

```text
endurance_outdoor
endurance_indoor
swim
strength_limited
recovery_limited
generic_limited
not_applicable
```

`not_applicable_reason` 仅在复盘受限或不适用时返回机器可读值；前端负责映射为产品文案，禁止直接暴露枚举：

```text
structured_strength_data_missing
recovery_activity_limited
generic_activity_limited
unsupported_activity_type
```

### 最小能力合同

`overview_capabilities` 的第一阶段最小集合为：

```text
has_track_visual
has_laps
has_structured_sets
has_swim_lengths
has_power
has_cadence
has_hr
has_weather
```

这些字段表达真实数据是否存在，不得仅因运动类型而伪造 `true`。`detail_surface_mode` 决定模块语义；实际字段能力决定模块是否可用。

### 路由和降级边界

- `running`、`trail_running`、户外骑行、徒步等保持 `endurance_outdoor`；`treadmill_running` 和 `indoor_cycling` 为 `endurance_indoor`，但维持既有 `review_mode=running/cycling`。
- `lap_swimming` 为 `swim_pool`，`open_water` 为 `swim_open_water`，二者 `review_profile=swim`。
- `strength_training` 为 `strength` / `strength_limited`；未解析 `set_mesgs`、`exercise_title_mesgs`、`workout_step_mesgs` 时必须使用 `structured_strength_data_missing`，不得推断动作、组数、重量、训练量或肌群。
- `yoga`、`pilates`、`breathing`、`flexibility_training` 为 `mobility_recovery` / `recovery_limited`；不得作竞速化表现评价。
- `cardio`、`training`、`hiit`、`stair_climbing`、`generic` 等默认 `generic_session` / `generic_limited`；只有后端已有的记录事实可决定可展示指标，不能前端猜测为耐力专项。
- `driving`、`unknown` 绝不默认落入跑步或骑行；使用 `not_supported` / `not_applicable` 和 `unsupported_activity_type`。

### UI 与 AI 禁止项

- 室内训练不展示地图失败、路线、爬升、天气或地形叙事；跑步机不展示 GAP/地形负荷；室内骑行不展示海拔/坡度空图。
- `not_applicable` 不渲染耐力图表、疲劳带、状态下滑事件或跑步/骑行指标。
- 游泳只消费已有的配速、SWOLF、划频、心率等事实，不使用 GAP、爬升、跑步配速或骑行功率推断。
- AI 只解释 snapshot 的事实、状态、能力与数据边界；不得推断路线、地形、天气、功率、动作、肌群、组数、负重或训练量。
